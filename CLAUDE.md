Architecture Decisions\
1. Blueprint Pattern for Routes

-   Why: Code organization, separation of concerns, easier maintenance

-   Each domain (incidents, personnel, equipment, etc.) has its own
    blueprint

-   Blueprints registered in app/routes/\_\_init\_\_.py\
    2. Role-Based Access Control

```{=html}
<!-- -->
```
-   Decorators: \@login_required, \@role_required(\'commander\', \...)

-   Why: Different users need different permissions

-   Enforced at route level, not just UI hiding\
    3. Separate Public and Staff Templates

```{=html}
<!-- -->
```
-   Public templates in templates/public/

-   Staff templates in templates/staff/ with subfolders

-   Why: Clear separation between public website and secure portal

-   Hidden entry points (/portal, /dispatch, /staff)\
    4. SQLite for Development

```{=html}
<!-- -->
```
-   Why: Zero configuration, file-based, perfect for single-developer
    projects

-   Future: Switch to PostgreSQL by changing DATABASE_URL in config\
    5. Leaflet for Maps (not Google Maps)

```{=html}
<!-- -->
```
-   Why: Free, open-source, no API key required for basic tiles

-   Leaflet.draw adds drawing capabilities for fire front annotation\
    6. Server-Sent Events for Notifications

```{=html}
<!-- -->
```
-   Why: Simpler than WebSockets, one-way communication is sufficient

-   Browser\'s EventSource API, reconnects automatically\
    7. WTForms for All Forms

```{=html}
<!-- -->
```
-   Why: Built-in CSRF protection, validation, rendering\
    8. App Factory Pattern

```{=html}
<!-- -->
```
-   create_app() function in app/\_\_init\_\_.py

-   Why: Allows multiple app instances, easier testing, better
    configuration management\
    \
    Coding Conventions\
    Python

```{=html}
<!-- -->
```
-   Imports order: standard library → third-party → local modules
    (alphabetical within groups)

-   Line length: 100 characters max (informal, not strict)

-   Naming:

    -   Classes: PascalCase (e.g., Incident, UserModel)

    -   Functions/Variables: snake_case (e.g., create_notification,
        list_firefighters)

    -   Constants: UPPER_SNAKE_CASE

    -   Blueprint names: snake_case_bp (e.g., incidents_bp)

```{=html}
<!-- -->
```
-   Docstrings: Used for complex functions, not for trivial
    getters/setters\
    Flask-Specific

```{=html}
<!-- -->
```
-   Route functions: def list_incidents(): (not incident_list)

-   Redirects use url_for(\'blueprint.function_name\')

-   Template variable names: all_incidents not incidents_list\
    Templates (Jinja2)

```{=html}
<!-- -->
```
-   Indentation: 4 spaces

-   Template inheritance: {% extends \"staff/base.html\" %}

-   URL generation: Always use url_for() with blueprint prefix\
    CSS

```{=html}
<!-- -->
```
-   Classes: kebab-case (e.g., notification-badge, skeleton-title)

-   Files: main.css (base), responsive.css (media queries), theme.css
    (variables)\
    JavaScript

```{=html}
<!-- -->
```
-   Functions: camelCase (e.g., updateNotificationCount, sendSOS)

-   Variables: camelCase

-   DOM element IDs: kebab-case (e.g., notification-badge, sosButton)\
    Database Models

```{=html}
<!-- -->
```
-   Table names: snake_case (SQLAlchemy auto-generates from class name)

-   Foreign keys: {table}\_id (e.g., vehicle_id, incident_id)

-   Relationships: backref for simple, back_populates for bidirectional\

    before adding new
